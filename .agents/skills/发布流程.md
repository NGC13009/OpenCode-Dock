# 发布流程（AI 专用技能）

适用项目：OpenCode Dock（VS Code 扩展）。任何 agent 执行「发布 / 发版 / 打包 / 出 vsix」时，**必须按本文顺序逐条执行**，不得跳步、不得颠倒。

## 适用范围

触发场景：用户要求「发布」「发版」「打个包」「出新版」「release」「出 vsix」等。
执行主体：任何 agent。发布是对外动作，**每次动手前先向用户确认版本号，得到同意再执行**。

---

## 步骤 1：确认版本号增加

版本号写在 `package.json` 的 `version` 字段（语义化版本 `MAJOR.MINOR.PATCH`）。按改动级别决定升哪一位：

| 改动级别 | 升级位 | 示例 | 判定标准 |
| --- | --- | --- | --- |
| 小功能 | PATCH（第三位） | 0.1.0 → 0.1.1 | 修 bug、文档、样式微调、行为不动的小改动 |
| 大功能 | MINOR（第二位） | 0.1.1 → 0.2.0 | 新增用户可见能力、新增设置项/命令 |
| 重构级 | MAJOR（第一位） | 0.2.0 → 1.0.0 | 架构级重构、破坏性变更、不兼容旧配置 |

- **级别有疑问时，先问用户，不要自己拍板。**
- 版本号的唯一来源是 `package.json`；README 只做同步，不得反过来以 README 为准。
- 同时更新 `README.md` 与 `README_CN.md` 两份文档中的版本号（正文版本行，形如 `v0.3.0 · VS Code ^1.106.0 · TypeScript`，以及安装示例里的 VSIX 文件名）。
- 改完核对 `package.json` 与两份 README 三处一致（以 `package.json` 为准）。
- 本次若有文案改动，确认四份本地化文件（`package.nls.json`、`package.nls.zh-cn.json`、`l10n/bundle.l10n.json`、`l10n/bundle.l10n.zh-cn.json`）已同步（详见 `.agents/rules.md` 的「国际化（i18n）约定」）。

## 步骤 2：确认 git 已提交

工作区必须干净（除有意保留的构建产物外），当前改动已提交。

```bash
git status --short      # 确认无未提交改动（构建产物 out/ media/ release/ 已 ignore 则不算）
git log --oneline -3    # 确认最新提交就是本次发版内容
```

- 有未提交改动 → **先提交再继续**，不要带着脏工作区发版。
- 提交信息建议直接用版本号（如 `0.1.1`），与既有提交风格保持一致。

## 步骤 3：编译

```bash
npm run compile
```

- 该命令执行主 tsconfig 编译（`tsc -p ./` → `out/`）。webview 方案已于 0.2.x 移除，不再有 webview 类型检查与 esbuild 步骤。
- **编译报错即中止发布**，修好再重来，不要用 `--force` 之类绕过。
- 编译通过后建议顺手跑测试：`npm test`（`pretest` 会自动再编译一次），测试不通过同样中止。

---

## 后续（当前尚未纳入标准流程）

以下步骤暂不属于本流程的必经环节，用户明确要求时再执行，并可在本文件追加为新步骤：

- 打包 VSIX 文件：`npm run package`（产出通用包，一个 VSIX 覆盖全部平台）。
- 安装产物：`code --install-extension .\release\opencode-dock-<version>.vsix`。
- 打 tag 并推送、GitHub Release。

---

## 一句话检查清单

发布前依次确认：① 版本号已按级别递增，且以 `package.json` 为准、与两份 README 一致 → ② `git status` 干净、改动已提交 → ③ `npm run compile` 通过（`npm test` 通过）。三项全绿才算发布准备就绪。
